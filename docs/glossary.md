# Glossary  
  
## General Terms  
  
| Term    | Abb. | Definition                                                                      |
| ------- | ---- | ------------------------------------------------------------------------------- |
| System  |      | The software application described and documented in this project.              |
| User    |      | A person who interacts with the system.                                         |
| Session |      | A workspace where users collaboratively perform estimation activities.          |
| Room    |      | The same as a session.                                                          |
| Task    |      | A unit of work that requires estimation by participants.                        |
| Ticket  |      | The same as a task.                                                             |
| Deck    |      | Set of tasks.                                                                   |
| Vote    |      | An estimation value submitted by a participant during a Planning Poker session. |

---

## Requirements  

| Term                       | Abb. | Definition                                                                                                                                 |
| -------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Functional Requirement     | FR   | A requirement that describes a function or behavior the system must provide.                                                               |
| Non-functional Requirement | NFR  | A requirement that defines quality attributes, constraints, or characteristics of the system, such as performance, security, or usability. |

---  
  
## Analysis and Design  

| Term                      | Abb. | Definition                                                                                                                             |
| ------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case                  | UC   | A description of the interaction between an actor and the system to achieve a specific goal.                                           |
| Actor                     |      | A user or external system that interacts with the application.                                                                         |
| Architecture              |      | The high-level structure of the system, including major components, their responsibilities, and relationships.                         |
| C4 Model                  |      | A software architecture visualization approach that describes a system on different levels: System Context, Container, Component, Code |
| System Context            |      | Defines system boundaries ans external interactions.                                                                                   |
| Container Component       |      | Defines system decomposition into runtime units.                                                                                       |
| Component Overview        |      | Defines internal structure of code services.                                                                                           |
| Code                      |      | Code.                                                                                                                                  |
| Entity-Relationship Model | ERM  | A data model that describes entities, their attributes, and relationships between them.                                                |
| Class Diagram             |      | A UML diagram that represents the static structure of the system, including classes, attributes, methods, and relationships.           |
| Sequence Diagram          |      | A UML diagram that shows interactions between objects over time.                                                                       |
| Activity Diagram          |      | A diagram that represents workflows, processes, and the sequence of activities within a system.                                        |
| Mockup                    |      | A visual representation of a user interface design.                                                                                    |
| User Flow                 |      | A representation of the steps a user follows to complete a task within the application.                                                |
  
---  
  
## Implementation  
| Term                              | Abb. | Definition                                                                                                |
| --------------------------------- | ---- | --------------------------------------------------------------------------------------------------------- |
| Application Programming Interface | API  | A defined interface that allows communication between different software components.                      |
| Architecture Decision Record      | ADR  | A document that records important architectural decisions, their context, alternatives, and consequences. |
| Code Structure                    |      | The organization of source code, modules, components, and project directories.                            |
  
---  
  
## Testing  

| Term          | Abb. | Definition                                                                                 |
| ------------- | ---- | ------------------------------------------------------------------------------------------ |
| Test Case     | TC   | A documented scenario used to verify whether a specific system behavior works as expected. |
| Test Strategy |      | A document describing the overall approach, scope, methods, and objectives of testing.     |
| Test Protocol |      | A record of performed tests and their results.                                             |

---  

## Traceability  

| Term                | Abb. | Definition                                                                                                                                     |
| ------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Traceability Matrix |      | A document that links requirements with related design elements, implementation parts, and test cases.                                         |
| Appendix            |      | An additional section of a document that contains supporting information that is useful for understanding but is not part of the main content. |

---

## Other
| Term                              | Abb. | Definition                                                                                                                                                                                                                       |
| --------------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| System Requirements Specification | SRS  | A document that describes the functions a software system must fulfill and the requirements (functional and non-functional) placed upon it. It serves as the basis for the development, testing, and acceptance of the software. |
